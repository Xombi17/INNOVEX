## Scope and guardrails

Frozen: `packages/engine/**`, `tests/engine/**`, `contracts/**`, `data/scope_catalog.json`, and `SPEC.md`. If a proven defect needs a frozen-file change, document it as a separate proposal; do not expand this milestone silently.

Expected edits: `.github/workflows/**`, `DEMO_SCRIPT.md`, `README.md`, `docs/**`, narrowly needed `apps/web/scripts/**`, web security/browser tests, and focused UI/accessibility fixes supported by evidence. Extension browser-check scripts may change if needed for repeatable verification; preserve its interception behavior. Update planning/evidence files to reflect actual results.

Use Node 24, Python 3, native APIs and existing scripts. Avoid new runtime dependencies or a new test framework. No database, accounts, extra providers, redesign, automatic account remediation or model-written security findings.

Preserve these invariants:

- RFC 7009 HTTP 200 includes invalid tokens; access-token cascading is SHOULD, and status alone is not proof of containment.
- GitHub OAuth grant deletion is `DELETE /applications/{client_id}/grant` with application-owner credentials; independent PATs require separate handling.
- PKCE S256 derives from the verifier, not scopes. Never rewrite a pending authorization; PKCE `safe_replacement_url` remains null.
- Configuration parsing stays local; no raw local input, credentials, authorization URLs or verification notes are sent to AI.
- AI may only reorder existing vetted facts. Keep request allowlists, streaming byte limits, redirect rejection, timeouts and fallback.
- Samples, supplied evidence, conditional consequences, incomplete coverage and self-reported remediation remain distinguishable. No fabricated credentials in empty scan results or invented user-study outcomes.

### 4. Prepare and run the five-person usability study

Reuse the protocol and targets in `docs/UX-VALIDATION.md`. Add a compact facilitator script and results template, suggested `docs/validation/v1.1.1-usability.md`.

Prepare tasks covering ten-second comprehension, explicit sample choice, local input, evidence versus unknowns, a provider action, and the meaning of checked-off/previewed remediation. Use built-in samples or clearly labeled inert fixtures, never live secrets. Record participant aliases rather than personal details.

For each session capture time, unprompted success, interventions, misunderstanding, a short participant quotation and the practical decision the tool helped them make. Avoid coaching before scoring.

Targets from the existing protocol:

- At least 4/5 complete the example unaided within two minutes.
- 5/5 distinguish example findings from their own accounts.
- 5/5 understand that the preview performs no remediation.
- At least 4/5 identify a practical next action.

The coding agent can prepare materials independently. Actual participant sessions require real participants; do not simulate people with an LLM or contact anyone without explicit user instructions. If participants are unavailable, finish the engineering work and label study results **Pending** with the exact next action. Do not block independent tasks or call the study passed.

Acceptance: either actual recorded results with supported conclusions, or a ready-to-run protocol and explicitly pending results. Only observed, repeated friction justifies follow-up UX changes.
