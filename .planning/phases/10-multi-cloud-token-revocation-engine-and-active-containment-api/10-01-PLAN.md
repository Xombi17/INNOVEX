# Phase 10 Plan 01: Multi-Cloud Token Revocation Engine & Active Containment API

## Objective
Elevate ScopeBomb from passive modeling to an active security remediation platform by providing real multi-cloud containment execution APIs (`/api/remediate`) and an interactive in-browser verification probe runner with a tamper-evident remediation ledger.

## Context
- `apps/web/src/app/api/remediate/route.ts`: New backend route for multi-cloud revocation simulation and probes.
- `apps/web/src/components/ContainmentComparison.tsx`: UI where containment steps are reviewed and verified.
- `apps/web/src/lib/remediationTemplates.ts`: Step details, copyable commands, and verification probes.

## Tasks
1. **Build Backend Remediation Endpoint (`/api/remediate/route.ts`):**
   - Accept containment step, issuer, target resource, and action type.
   - Support dry-run execution and simulated cloud SDK actions for AWS (STS/IAM), GitHub (OAuth App grants/PATs), and Google.
   - Execute verification probe simulation returning actual HTTP response headers and status codes (204, 401, 403).
   - Generate tamper-evident audit ledger entries with cryptographic hash (SHA-256) and ISO timestamp.
2. **Add "Run Active Verification Probe" to Containment UI:**
   - Add a direct execution button `[ ⚡ Run Live Verification Probe ]` on each containment card in `ContainmentComparison.tsx`.
   - Display a terminal-style execution output box with probe response, status code, and verifiable audit receipt.
3. **Verification:**
   - Unit/integration test for `/api/remediate`.
   - Verify `npm run build --prefix apps/web`.
   - Verify engine tests (`node --test tests/engine/*.test.ts`).
